# RAG Knowledge Assistant

A portfolio-oriented RAG (Retrieval-Augmented Generation) knowledge assistant. The application accepts PDF uploads through FastAPI, uses MinerU to parse documents into Markdown, splits and embeds the content with BGE-M3, and stores dense and sparse vectors in Milvus. During question answering, it performs hybrid retrieval, RRF fusion, reranking, and LLM generation while preserving conversation history in MongoDB.

The project highlights practical AI application engineering across document ingestion, vector retrieval, workflow orchestration, model integration, and API delivery.

## Technology Stack

- Python 3.11
- FastAPI and Uvicorn
- LangGraph workflow orchestration
- MinerU PDF parsing API
- BGE-M3 embeddings (dense and sparse)
- Milvus vector database
- Reciprocal Rank Fusion (RRF)
- DashScope TextReRank
- LLM access through an OpenAI-compatible API
- MongoDB conversation history
- Docker Compose, etcd, MinIO, and Milvus Standalone

## Architecture

### Document Ingestion

```text
PDF upload
  → local file storage
  → MinerU parsing
  → Markdown
  → skip image processing when no image directory exists
  → heading-based splitting, long-chunk splitting, and short-chunk merging
  → BGE-M3 dense and sparse embeddings
  → Milvus collection and insertion
```

### RAG Question Answering

```text
Question + session_id
  → load MongoDB history
  → rewrite the follow-up question
  → BGE-M3 hybrid retrieval
  → HyDE hybrid retrieval
  → RRF fusion
  → DashScope reranking
  → assemble retrieved context and conversation history
  → generate an LLM answer
  → save the answer to MongoDB
```

## Core Features

- PDF upload through Swagger UI or HTTP.
- PDF-to-Markdown parsing through MinerU.
- Markdown-aware chunking with long- and short-chunk handling.
- Dense and sparse embeddings generated by BGE-M3.
- Milvus collections, indexes, insertion, and idempotent updates for documents with the same title.
- Standard semantic retrieval and HyDE retrieval fused with RRF.
- Candidate reranking through DashScope TextReRank.
- LLM answers grounded in reranked knowledge chunks.
- Multi-turn context identified by `session_id` and stored in MongoDB.
- Upload, chat, history, and basic SSE endpoints exposed through FastAPI.

## API Endpoints

| Method | Path | Description |
| --- | --- | --- |
| `POST` | `/upload` | Upload a PDF and synchronously parse, chunk, embed, and index it |
| `POST` | `/chat` | Run RAG question answering with a `session_id` and streaming option |
| `POST` | `/query` | Deprecated compatibility endpoint for older clients |
| `GET` | `/stream/{session_id}` | Receive SSE events for a streaming request |
| `GET` | `/history/{session_id}` | Read the conversation history for a session |
| `GET` | `/chat.html` | Open the bundled chat page |

After starting the API, Swagger UI is available at `http://127.0.0.1:8001/docs`.

## Requirements

- Windows
- Python 3.11
- Docker Desktop
- MongoDB, available at `localhost:27017` by default
- A valid MinerU API token
- A valid DashScope/OpenAI-compatible API key
- A local BGE-M3 model or network access for downloading it

Docker Compose starts etcd, MinIO, and Milvus Standalone. MongoDB is not included in the current Compose file and must be started separately.

## Configuration

Create the local environment file:

```powershell
Copy-Item .env.example .env
```

Review at least the following settings:

```dotenv
MINERU_API_TOKEN=your-mineru-token
OPENAI_API_KEY=your-api-key
OPENAI_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_DEFAULT_MODEL=qwen-flash

BGE_M3_PATH=./data/models/bge-m3
BGE_M3=BAAI/bge-m3
BGE_DEVICE=cpu

TEXT_RERANK_MODEL=your-dashscope-rerank-model
TEXT_RERANK_INSTRUCT=

MILVUS_URL=http://localhost:19530
CHUNKS_COLLECTION=kb_chunks
MONGO_URL=mongodb://localhost:27017
MONGO_DB_NAME=kb001

UPLOAD_DIR=./data/uploads
OUTPUT_DIR=./output
```

Never commit real API keys to version control.

## Getting Started

### 1. Create the environment

```powershell
cd C:\Users\<username>\AIProjects\knowledge_base_0525
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Select the CPU or CUDA build of PyTorch according to the local machine. The application falls back to CPU when CUDA is unavailable.

### 2. Prepare BGE-M3

Place the model in the directory configured by `BGE_M3_PATH`. The example configuration uses `./data/models/bge-m3`.

### 3. Start Milvus

```powershell
docker compose up -d
docker compose ps
```

### 4. Start MongoDB

Ensure that MongoDB is listening at the address configured in `.env`; the default port is `27017`.

### 5. Start FastAPI

```powershell
python -m uvicorn web.api.query_service:app --host 127.0.0.1 --port 8001
```

Add `--reload` for local development if needed.

## Quick Test

1. Open `http://127.0.0.1:8001/docs`.
2. Use `POST /upload` to upload a PDF and wait for a response containing `chunks_count`.
3. Call `POST /chat`:

```json
{
  "query": "What is this document mainly about?",
  "session_id": "demo-session-001",
  "is_stream": false
}
```

4. Ask a follow-up question with the same `session_id` to verify multi-turn context.
5. Call `GET /history/demo-session-001` to inspect the messages stored in MongoDB.

The current `/upload` endpoint processes documents synchronously. Processing time for a large PDF depends on MinerU latency, embedding performance, and document length.
